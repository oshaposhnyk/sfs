Custom Learning Plans Plugin
----------------------------

Implement a custom Moodle plugin for SecureFood School learning plans.

Do not confuse this with Moodle core competency learning plans unless the project explicitly decides to integrate with competencies later.

Recommended plugin split:

1. local_sfsplans
This plugin owns learning plan management, data model, web services, scheduled tasks, event observers, progress aggregation, and admin reports.

2. enrol_sfsplan
This optional enrolment plugin owns enrolment behavior when a user is enrolled into a learning plan. If the team chooses to avoid a separate enrol plugin, local_sfsplans must still use Moodle enrolment APIs cleanly and explicitly.

Learning plan features:
- Create, edit, archive, and hide learning plans
- Group courses into ordered stages/sections
- Sort courses within each stage
- Mark courses as required or optional
- Define prerequisites/unlock rules
- Enrol a user directly into a learning plan
- Automatically enrol a learning plan user into all courses in that plan
- Link one or more Moodle cohorts to a learning plan
- Automatically enrol a user into a learning plan when the user is added to a linked cohort
- Automatically enrol the user into all courses of that learning plan
- Reconcile missing enrolments with a scheduled task
- Keep a sync log with success/error details
- Support a removal policy when a user is removed from a linked cohort

Removal policy options:
- Suspend learning plan enrolment only
- Suspend course enrolments
- Fully unenrol from learning plan and courses
- Keep enrolment but mark source cohort as removed

Events and Synchronization
--------------------------

Implement Moodle event observers.

Observer: cohort_member_added
- Detect when a user is added to a cohort.
- Find all active learning plans linked to that cohort.
- Create or update the user's learning plan enrolment.
- Enrol the user into all required Moodle courses in the plan.
- Use the configured roleid for course enrolment.
- Write sync log entries.
- Trigger notification if enabled.

Observer: cohort_member_removed
- Detect when a user is removed from a cohort.
- Find learning plan enrolments sourced from that cohort.
- Apply the configured removal policy.
- Write sync log entries.
- Trigger notification if needed.

Scheduled reconciliation task:
- Iterate active cohort-plan mappings.
- Compare cohort members against local_sfsplans_user records.
- Create missing learning plan enrolments.
- Repair missing course enrolments.
- Detect invalid course mappings.
- Detect suspended/deleted users.
- Write sync log entries.
- Produce admin-visible summary statistics.

Completion aggregation task/API:
- Calculate course progress from Moodle completion APIs.
- Calculate stage progress from courses in each stage.
- Calculate learning plan completion percentage.
- Mark learning plan completed when all required courses are complete.
- Persist completion timestamp in local_sfsplans_user.

Known Risks and Limitations
---------------------------

The report must explicitly mention these risks:

- Learning plan removal policy must be agreed before production rollout.
- Local cached data must not become the source of truth.
- Moodle remains the source of truth for users, courses, enrolments, completion, grades, and notifications.
